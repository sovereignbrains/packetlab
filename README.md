# packetlab

Модульный установщик и меню управления мультипротокольным прокси-стеком.

## Установка

```bash
wget -qO- https://raw.githubusercontent.com/sovereignbrains/packetlab/main/install.sh | bash
```

На чистом Debian 13 есть `wget`, а `curl` нет — установщик поставит его сам.
Если `curl` уже стоит, можно и `curl -fsSL … | bash`.

Debian 13, x86_64, root. Установщик спрашивает домен — дальше развилка:

- **с доменом** — домен в Cloudflare и API-токен с правами `Zone:DNS:Edit`:
  wildcard-сертификат по DNS-01, decoy-сайт, подписка, все протоколы.
  Zone ID установщик находит по токену сам, спрашивает — только если токен зону не видит;
- **без домена** (пустой Enter) — ни Cloudflare, ни сертификата: доступны REALITY,
  AnyTLS + REALITY, ShadowTLS v3, Hysteria2, Mieru и Telegram MTProxy, в ссылках IP сервера, подписки нет (ссылки и QR — в меню).

Без интерактива (удобно для нескольких серверов):

```bash
PL_DOMAIN=example.com PL_CF_TOKEN=... PL_CF_ZONE=... \
  bash <(wget -qO- https://raw.githubusercontent.com/sovereignbrains/packetlab/main/install.sh)

PL_NO_DOMAIN=1 bash <(wget -qO- https://raw.githubusercontent.com/sovereignbrains/packetlab/main/install.sh)
```

- `PL_REF=<коммит|тег|ветка>` — взять все файлы с этой версии (по умолчанию `main`); записывается в `meta.json` как `ref`.
- `PL_YES=1` — не задавать вопросов, на которые можно ответить «да» (не-Debian): для установки без терминала.
- Порты, на которых слушает `sshd` (и `Port` из его конфига), открываются в ufw до сброса — вход не теряется и на нестандартном порту.

⚠️ Установщик выполняет `ufw --force reset` — запускать только на чистом
сервере, иначе снесёт существующие правила firewall.

## Управление

```bash
packetlab            # меню
packetlab outbounds  # для машины: один JSON {"outbounds":[...]} всех стоящих протоколов (формат sing-box)
packetlab status     # диагностика: конфиг / порт / firewall
packetlab sub        # ссылка-подписка
packetlab qr         # QR подписки (Karing, Hiddify); packetlab qr singbox — импорт в приложение sing-box
packetlab link uri   # все ноды списком
packetlab install anytls-reality   # поставить модуль без меню
packetlab install all              # все протоколы, которые сервер может поднять (в меню — «a»)
packetlab tune                     # тюнинг ядра из lib/sysctl.conf: BBR+fq, буферы 32 МБ, очереди (в расширенном меню — «t»)
```

`install all` ставит по очереди всё, чего ещё нет (без домена — только REALITY,
AnyTLS + REALITY, ShadowTLS v3, Hysteria2, Mieru и Telegram MTProxy), каждый протокол со своими проверками; упавший не
останавливает остальные, в конце — итог. sing-box перезапускается на каждом.

## Что внутри

| Слой | Чем |
|---|---|
| Вход 443/tcp | haproxy, SNI-роутинг без терминации TLS |
| Вход UDP | sing-box напрямую |
| Ядро | одно — официальный sing-box (SagerNet); уже стоящий установщик не заменяет и не понижает |
| Протоколы | REALITY, AnyTLS + REALITY, ShadowTLS v3 (shadowsocks-2022 внутри; клиентское звено — два outbound через detour, подписка отдаёт оба), AnyTLS + ECH, NaiveProxy, Hysteria2 — инбаунды sing-box (Mieru — только если стоящее ядро его знает, сборка [mbox](https://github.com/enfein/mbox) ставится вручную); Telegram MTProxy ([telemt](https://github.com/telemt/telemt), FakeTLS, свой бинарник и служба) — вне подписки, ссылки `tg://` в меню; с доменом ещё WEB-прокси Telegram (`tg://webproxy`, через Caddy, случайный путь) |
| Маскировка | Caddy, decoy-сайт (с доменом); без домена чужой SNI уходит в REALITY |
| Подписка | один URL, формат по User-Agent |

### Hysteria2 и фильтр UDP

У части провайдеров UDP режут или душат. Поэтому Hysteria2 ставится и без домена, а при
новой установке — всегда с обфускацией **salamander** (QUIC не узнать по рукопожатию).
`gecko` — только вручную, `packetlab reconfig hy2 obfs=gecko`, и только если проверено,
что у этого провайдера он проходит и клиент его понимает.

- **Без домена** — самоподписанный сертификат на `www.example.com` в
  `/etc/packetlab/hy2.{crt,key}`, клиент сверяет пин: `certificate_public_key_sha256` в
  sing-box, `insecure=1&pinSHA256=` в ссылке. Порт — 443/udp (haproxy держит только tcp).
  Сертификат не перевыпускается, пока модуль стоит.
- **Перескок портов** — UDP 20000–20100 перенаправляются на порт Hysteria2 таблицей
  `inet plhop` (служба `packetlab-hop`). В ссылках — второй outbound
  `Hysteria2 · порты 20000-20100` (`server_ports`, `hop_interval` 20s), `mport=` в uri.
  Если nftables не дал NAT (контейнер), модуль ставится без перескока и говорит об этом;
  `packetlab reconfig hy2 hop=on|off`.
- С доменом — как раньше: Let's Encrypt, порт 9445.
- Если UDP закрыт совсем, клиент уходит на TCP-протоколы (REALITY, AnyTLS + REALITY,
  ShadowTLS) — они стоят рядом.

Подписка — sing-box JSON с `urltest`. Karing и Hiddify получают всё, официальный
клиент sing-box — без Mieru: он этого протокола не знает (модуль помечен
`MOD_CLIENTS=extended`).

## Пользователи

У каждого пользователя в каждом протоколе свои ключи (uuid / пароль) и своя
ссылка-подписка: подписка по его токену отдаёт его ключи, удаление убирает их
из всех инбаундов — доступ пропадает сразу, а не только ссылка. Меню → `u`:
список, карточка пользователя (ссылка, QR, ссылки протоколов, смена ссылки,
удаление), добавление. Добавление и удаление перезапускают sing-box.

Хранится в `/etc/packetlab/users.json`, логика — `lib/users.py`. Первый в списке —
владелец; при обновлении со старой версии он забирает прежние ключи из
`meta.json`, так что ссылки не меняются (`packetlab users-sync` дописывает
пользователей в уже установленные инбаунды, sing-box трогается только если
конфиг реально поменялся).

## Модули

Протокол — один файл в `modules/`, объявляющий метаданные и четыре функции:
`mod_status`, `mod_install`, `mod_remove`, `mod_link <формат> [пользователь]`.
`MOD_USERS` — шаблон записи пользователя в инбаунде (`%name%`, `%uuid%`, `%pass%`).
Необязательная `mod_can_install` говорит, может ли модуль встать на этом сервере
вообще (Mieru — только на ядре со сборкой mbox); «установить все» пропускает ответивших «нет». Меню сканирует папку и
подхватывает новый файл само, править диспетчер не нужно.

`mod_status` сверяет три источника — конфиг, реально слушающий порт и правило
firewall — и различает `down` (не слушает) и `blocked` (слушает, но порт
закрыт). Правило UFW создаётся и удаляется вместе с инбаундом, поэтому
рассинхрон конфига и firewall невозможен.
## Вход → выход (中转 → 落地)

Клиенты подключаются к одному серверу (вход), а в интернет выходят с другого (выход).
Подписка не меняется — сайты просто видят IP выхода. Между серверами — VLESS + REALITY:
выходу не нужны ни домен, ни сертификат, а канал вход → выход устойчив к DPI (нужно, когда
вход стоит в стране с фильтрацией).

Всё делает `relay/plr.sh` — один файл, обе роли, packetlab для него не нужен. На серверах с
packetlab он уже стоит как `plr` и доступен из меню (`r`).

```bash
# на сервере без packetlab
curl -fsSL https://raw.githubusercontent.com/sovereignbrains/packetlab/main/relay/plr.sh \
  -o /usr/local/bin/plr && chmod +x /usr/local/bin/plr

plr exit             # на выходе: поднять relay-in и напечатать токен plr1.…
plr link <токен>     # на входе: связать; трафик клиентов пока идёт напрямую
plr test             # запрос через проверочный порт должен вернуться с IP выхода
plr on               # весь трафик клиентов — через выход (plr off — обратно)
plr unlink           # на входе: убрать связку;  plr exit --remove — на выходе
```

Токен — это секрет (внутри ключи выхода), с контрольной суммой: обрезанная вставка
отлавливается сразу. `plr on` не переключит трафик, пока не пройдёт проверка. Каждое
изменение перезапускает sing-box — активные соединения через сервер обрываются.
